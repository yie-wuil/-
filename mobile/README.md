# 时光轴  手机版 v0.5.0

一个**以时间规划为核心**的日程工具。第一优先级：**到点一定响，且能直接在通知上打勾。**

> 手机没有托盘常驻、不能开机自启、进程随时会被杀。所以提醒不是"应用内轮询"，
> 而是**提前把通知交给系统托管**，应用死了也照响。

## 二、 必做：让提醒真正响起来（6 步）

**不做完这几步，提醒可能不会响。** 这是 Android 系统限制，不是 App 的问题。

| # | 设置项 | 路径 | 为什么必须 |
|---|---|---|---|
| 1 | **通知权限** | App 内顶部横幅，或 设置  应用  时光轴  通知  允许 | 没权限一条都收不到 |
| 2 | **精确闹钟** | 设置  应用  时光轴  闹钟和提醒  允许 | Android 12+ 默认关闭，不开就无法准点 |
| 3 | **电池优化** | 设置  应用  时光轴  电池  不限制 | 省电模式会延迟甚至吞掉提醒 |
| 4 | **自启动** | 设置  应用  时光轴  自启动  打开 | 部分国产 ROM 必做 |
| 5 | **后台运行** | 设置  应用  时光轴  后台运行  允许 | vivo / OPPO 等需要 |
| 6 | **锁定后台** | 最近任务里下拉时光轴  加锁 | 防止一键清理时被杀 |

**验证**：App 内「我的  发一条测试提醒」，5 秒后应收到通知。

**更严格的验证**（建议做一次）：
- 从最近任务划掉 App  到点还响吗？
- 重启手机  到点还响吗？
- 开省电模式  到点还响吗？

## 三、界面结构（4 个 Tab）

```
[清单]  [日历]  [目标]  [我的]
```

> v0.3 起「收集箱」不再是独立 Tab  它降级为清单底部的「未安排」分组。
> 这是刻意的：**工具的目标是"把事排到时间上"，不是"囤积想法"。**

### 1. 清单（默认首页）

按日期分组的任务列表，这是时间规划的主战场：

```

 [今天] [最近 7 天] [全部]    
 今天 2/4           
                             
 已逾期 2      全部顺延       
  提交报销单          全天   
  打电话         10:00 10:30 
                             
 今天 2/4              + 添加 
  项目周会       10:00 11:00 
  写项目周报     14:00 15:00 
  读书 30 分钟   20:30 21:00 
                             
 明天 0/2              + 添加 
  牙医预约        09:00      
                             
 未安排 2                     
  买牛奶                     
  预约牙医        [][]     

                     ( + )   FAB
```

- **时间右置**，一眼看清每件事占用哪一段
- 进行中的任务会高亮描边
- 「未安排」在底部，右侧两个按钮可一键排到今天 / 明天
- 逾期不再静默顺延，**让你看见并主动决定**

右上角 **** 菜单提供三个动作：

| 动作 | 说明 |
|---|---|
| 隐藏已完成 | 列表里不再显示打勾的任务（设置会记住） |
| **清除已完成** | 一键删掉所有已完成任务，菜单里显示待清除条数；**重复任务不会被清**（它是常驻系列） |
| 顺延逾期到今天 | 把逾期任务批量搬到今天 |

删除后 5 秒内可点「撤销」完整恢复。

### 2. 日历

顶部切换「月 / 时间轴」：

- **月视图**：月历 + 下方选中日期的任务列表，可前后翻月
- **时间轴**：24 小时垂直排布，任务块按 `开始时间 + 时长` 占位，红线标当前时刻

时间轴是"看见时间去哪了"的关键视图。

### 3. 目标

目标卡（进度条 + 目标值）。**点进去是目标详情**：

- 内联输入框，直接为该目标添加任务
- 可选「仅一次 / 每天 / 工作日 / 每周」
- 支持自然语言（`明天下午3点 整理卡片 45分钟`）
- 列表里直接勾选完成**今天这一次**

例：目标「读完 12 本书」+ 每日任务「读书 30 分钟」 每次完成，目标进度 +1。

### 4. 我的

统计（今日完成 / 本周完成 / 连续天数）+ 提醒设置 + 数据备份。

## 三之二、提醒健康检查

提醒是本产品唯一不可替代的价值，所以它必须**可见、可测、可修**。

**入口**

| 位置 | 何时出现 |
|---|---|
| 清单页顶部状态条 | 仅在检测到异常、且**已创建过带时间的任务**时出现（避免骚扰新用户） |
| 我的  查看提醒健康检查 | 常驻，随时可打开 |

**检测 4 项**

| 项 | 检测方式 | 异常含义 |
|---|---|---|
| 通知权限 | checkPermissions() | 提醒完全收不到 |
| 提醒渠道 | listChannels() 取 importance，为 0 即被用户关闭 | 到点不会响 |
| 准时性 | checkExactNotificationSetting()（内部 canScheduleExactAlarms） | 提醒可能晚 5~15 分钟 |
| **电池白名单** | `PowerManager.isIgnoringBatteryOptimizations()`（经原生插件） | 省电模式下提醒可能被延迟或拦截 |
| **厂商自启动** | Android 无 API，仅引导；用户点过「去设置」后置为正常 | 小米/华为/OPPO/vivo/三星 锁屏后可能被拦截 |

**三态**

| 状态 | 条件 | 表现 |
|---|---|---|
| 正常 | 全部通过 | 状态条完全隐藏，不占视觉 |
| 可能延迟 | 准时性 / 渠道 / 后台 任一异常 | 浅黄细条「提醒可能晚几分钟  去优化」 |
| 收不到 | 通知权限被拒 | 浅红细条「提醒收不到  去开启」 |

设计原则：只让异常可见；界面不出现术语（精确闹钟、SCHEDULE_EXACT_ALARM）；不弹窗不阻断；提供「暂时不用」（7 天免打扰）。

## 三之三、系统广播与自动重排

复用插件自带的 LocalNotificationRestoreReceiver（在 manifest 里追加 intent-filter，manifest merger 自动合并，无需写自定义 Java）：

| 广播 | 作用 |
|---|---|
| BOOT_COMPLETED | 开机后恢复闹钟（插件自带） |
| TIMEZONE_CHANGED / TIME_SET | 重新挂载闹钟。注意：插件存储只保留绝对时间戳，时区变更后还需 App 层重算本地时刻，因此同时实现了 checkEnvChange()，在启动/回到前台时比对时区并全量重排 |
| DATE_CHANGED | 跨天刷新 |
| MY_PACKAGE_REPLACED | App 更新后重排 |

## 四、快速添加（FAB）

右下角 **+** 按钮，任意页面可用：

```

 明天下午3点开会 1小时 #工作    
 将创建：明天 15:00 1 小时 #工作  开会 
                              
 [今天] [明天] [后天] [选日期] [不安排] 
                    [取消] [添加] 

```

- 支持：今天/明天/后天/大后天、周一到周日（含下周）、上午下午晚上、`15:00`、`3点半`、`1h`/`30分钟`、`#分类`
- **不写日期默认排到今天**（时间规划导向）
- 点「不安排」则存入未安排

## 七、已知限制

1. **只有 Android 版**。iOS 需 macOS + Xcode 构建。

## 七之二、本地原生插件（SystemSettings）

JS 层无法打开系统设置页，所以写了一个约 200 行的本地插件补齐：

| 方法 | 作用 | 降级链 |
|---|---|---|
| `getDeviceInfo()` | 返回 厂商 / 型号 / SDK / **是否已加入电池白名单** / 是否可精确闹钟 |  |
| `openChannelSettings({channelId})` | 直达通知渠道设置 |  应用通知设置  应用详情页 |
| `openBatteryOptimization()` | 直达"不受限制"授权弹窗 |  电池优化列表  应用详情页 |
| `openAutoStart({vendor})` | 直达厂商自启动页 |  各厂商多组 Intent 依次尝试  应用详情页 |
| `openAppDetailsSettings()` | 应用详情页 |  |

**覆盖的厂商自启动 Intent**

| 厂商 | 尝试的组件 |
|---|---|
| 小米/红米 | `com.miui.securitycenter/.permcenter.autostart.AutoStartManagementActivity` |
| 华为/荣耀 | `com.huawei.systemmanager/.startupmgr.ui.StartupNormalAppListActivity` 等 2 组 |
| OPPO/一加/realme | `com.coloros.safecenter` 2 组 + `com.oplus.safecenter` + `com.oneplus.security` |
| vivo/iQOO | `com.vivo.permissionmanager/.activity.BgStartUpManagerActivity` 等 2 组 |
| 三星 | `com.samsung.android.lool/.sm.ui.battery.BatteryActivity` 等 2 组 |

> 每一条都先 `resolveActivity()` 判存在再跳，全部失败则降级到应用详情页  保证用户永远有路可走。

## 七之三、通知渠道说明

| 渠道 id | 名称 | importance | 说明 |
|---|---|---|---|
| `reminders_v2` | 任务提醒 | 5 (MAX) | 到点提醒，需要 heads-up |

>  **Android 硬限制**：NotificationChannel 创建后 `importance` **无法通过代码修改**。
> 所以 v0.3.x 用过的旧渠道 `reminders` 已在启动时删除，改用 `reminders_v2`。
> **若将来要做「安静模式」（降为 4），必须新建第二个渠道**（如 `reminders_quiet`），切换时把所有通知重排到新渠道  同一渠道无法降级。
